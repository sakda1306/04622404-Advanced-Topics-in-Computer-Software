# End-to-end API test

Runs the whole user flow against the running Docker stack through the web proxy
(`http://localhost:3000/api`), so the Next.js proxy and the api are tested together.

## Run

```bash
docker compose up --build -d          # from the repo root, with your .env
python3 e2e/e2e_api.py
```

- Needs only the Python standard library. The test PDFs are generated by the script.
- Test accounts use `@example.com` and are deleted at the end of the run.
- Admin checks need `e2e-admin@example.com` in `ADMIN_EMAILS` (add it to `.env`,
  run `docker compose up -d api`, and remove it again after the run). Another
  address can be set with `E2E_ADMIN_EMAIL`.
- Cost: about 6 Groq requests from the daily quota. No Apify calls.

## Logs

Every run writes `runs/<date>_<time>_<commit>.log` with the branch, commit, all
PASS / FAIL lines, notes (parse counts, match %, routes, timings, quota) and a summary.
Compare two runs with:

```bash
diff e2e/runs/<older>.log e2e/runs/<newer>.log
```

## Test groups

| Group | What it checks |
|---|---|
| A. Health and auth | health, register (duplicate 409, short password 422, no consent 422), login (401, 429 after 5 failures), `/auth/me` |
| B. CV | non-PDF 415, over 5 MB 413, no text layer 422, text PDF parse, `GET /cv`, confirm |
| C. Questionnaire | sections, O\*NET attribution, every answer type saved, unknown question 404, too many choices 422, resume |
| D. Profile and roles | generate not ready 409, generate, evidence on every skill, match list, role detail, unknown role 404, remove / restore skill, preferences, explain, market |
| E. Chat and edits | salary, skill and off-topic routes, over 1,000 characters 422, history, edit proposals: confirm, reject, repeat confirm, unknown 404 |
| F. Quota, admin, cleanup | quota headers vs `/quota`, admin 403 for a normal user, overview for `today` / `7d` / `30d` without emails, logout, delete account |

## Known limits (run of 4 Nov 2026)

- `role_cache` was empty, so market checks ran on the "no data yet" state. Run
  `api/scripts/seed_market.py` first (spends Apify credits) to test listings.
- The explain step found no stale roles, because restoring the removed skill
  brought the matches back to their earlier state, so the LLM rewrite path was not exercised.
